# INTEGRATION COMPLETION REPORT — Measur Business College portal <-> Virtual Business Lab

**VBI codes: 50 implemented on the portal side · 0 PARTIAL · 0 NOT IMPLEMENTED (of 50). (Batch 66 closed VBI027/036/038.)**
**Batch 66 caveat, read first:** VBI027 and VBI036 need the *Lab* to send two additive, optional payload fields (`criteria` on `assessment.decided`; richer `activity.logged`). The portal now accepts and uses them (contract updated), but the Lab repository was not part of this batch — until it emits them the portal behaves exactly as before for those two codes. See `docs/progress-batch66.md`.
"COMPLETE" here means: the logic is implemented AND exercised by tests that actually ran. It does **not** mean "verified on a live Postgres + Express + FastAPI stack" — see *Remaining blockers*.

## What was verified by executed tests
* Lab (Python): full suite green across 28 test modules (the integration adds ~60 tests incl. real-socket retry tests).
* Portal integration modules (TypeScript): pure-logic tests green in the batch-66 sandbox (backoff, secret-box, rubric-mapping, JWT-secret guard, signing, versioning, contract). **The Postgres-backed suites (`tests/db/*`, 78 tests) and the E2E were written in batch 66 but NOT run — the sandbox has no Postgres. Run `npm run test:db` first.** (Batches ≤65 ran the same scenarios against an in-memory Prisma stand-in, which has been removed.)
* **Cross-system E2E** (`e2e/run_e2e.py`): real Lab code <-> real portal modules over real sockets, 3 scenarios incl. portal-down recovery, duplicate redelivery, approve -> grade posted -> confirmation, reversal, and retry-after-failure in both directions. Mutation-checked.
* Contract tests on both sides against one shared JSON contract.

## Remaining blockers (read before deploying)
1. **REQUIRES REAL STACK — NOT DONE:** `npx prisma validate && npx prisma migrate dev`. The new models (7 models, 3 enums, additive fields on Student/Trainer/Unit/Enrollment/Assessment/Submission/LearningOutcome) were checked only for brace balance/duplicates and reviewed by hand; Prisma itself never ran.
2. **NOT VERIFIED:** Express route glue (`routes/integration-vbl.ts`), FastAPI adapter (`vbl/api/app.py` — was already "never run" before this work), and every Prisma query against a real database.
3. **FRONTENDS — UNCOMPILED.** (Batch 66 added the admin console `/admin/virtual-lab`, the trainer criteria view and the student activity feed; trainer review is now restricted to units the trainer teaches. Syntax-checked with esbuild only.) Older note follows. Added: student page `/student/virtual-lab` (launch button + own results with status/reversal reasons) and trainer page `/trainer/virtual-lab` (review queue with approve / reject / admin-reverse, gradebook-posting feedback), routes in `App.tsx`, nav links (38 student pages + the shared trainer list). **They have never been compiled or rendered** (no `node_modules`/`tsc`/browser in the build sandbox) — run `npm run build` first. **Not built:** admin screens for the sync dashboard, credentials, and course/gradebook/competency mappings (JSON APIs only), and any Lab UI beyond the `/lab` SSO landing page. Trainer review is not yet restricted to a trainer's own courses (any TRAINER can review any result).
4. **REQUIRES EXTERNAL CREDENTIALS:** issuing real signing credentials, `PORTAL_SSO_SECRET` etc. (code complete; nothing seeded).
5. **Schedulers:** Batch 66 added an in-process scheduler (`integration/scheduler.ts`, Postgres advisory lock, on by default when `VBL_INTEGRATION_URL` is set). The Lab side still needs `tools/sync_worker.py` running.
6. Known limits: HMAC shared-secret SSO; signing secrets are now AES-256-GCM encrypted at rest (set `INTEGRATION_SECRET_ENCRYPTION_KEY`; the key still lives in the process environment, so a KMS-sourced key is better); rate limiter is now Postgres-backed; one gradebook component per unit (not a weighting engine); single Lab institution (`VBL_DEFAULT_INSTITUTION_CODE`).

## Bugs the tests found in this integration's own earlier code (all fixed)
retry backoff clock never advanced after a failure · FAILED event acknowledged as a duplicate on redelivery (silent permanent loss, **both** systems) · non-existent permission string in Lab RBAC · signature over re-serialised JSON · a test-only `Assessment` schema edit that had briefly corrupted `schema.prisma` (caught by brace check, repaired, verified).
